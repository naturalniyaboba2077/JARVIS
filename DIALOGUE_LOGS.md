# История диалогов Jarvis

Диалоги сохраняются локально в **`C:\Users\user\Documents\Jarvis\logs\dialogues`**.
Чтобы включить новую реализацию, полностью закройте старый Jarvis и запустите
обычным ярлыком или `launch_jarvis.bat`. Запись начинается с первой новой реплики;
выдуманных примеров и восстановленных задним числом разговоров в журнале нет.

В папке появляются пары файлов:

```text
dialogue_2026-09-05_<сессия>.txt
dialogue_2026-09-05_<сессия>.jsonl
```

`.txt` удобно открыть в Блокноте. `.jsonl` содержит те же реплики с отдельными
полями и предназначен для диагностики. Новый запуск имеет отдельный идентификатор
сессии; при переходе через полночь создаётся файл нового дня без перезапуска.
Старые файлы не перезаписываются и автоматически не удаляются.

## Что записывается

- Команды из текстового поля и распознанные голосовые команды, прошедшие фильтр
  обращения к Jarvis. Посторонняя речь, отброшенная этим фильтром, в новый журнал
  диалога не добавляется. Аудио этот модуль не записывает.
- Ответы, переданные для отображения: быстрые команды, обычные ответы, результаты
  инструментов и ошибки, показанные пользователю, уведомления и «Начинаю поиск».
- Потоковый ответ — одной репликой при завершении, без записи каждого токена.
  При отмене сохраняется последняя часть, переданная в интерфейс, с отметкой
  `interrupted`; при сбое потока — `incomplete`.
- Нажатие кнопки «Стоп» отмечается отдельно. Поля настроек, пароли авторизации
  и служебные ответы модели с ещё не выполненными тегами специально не записываются.

У каждой записи есть время с часовым поясом, сессия, порядковый номер, участник,
источник (`text`, `voice`, `response`, `stream`, `control`) и статус.
`received` означает принятую команду, `displayed` — переданный в интерфейс ответ,
`complete` — завершённый текстовый поток. Это **не доказательство**, что звук
физически прозвучал полностью или что заявленный моделью результат верен.

## Как прочитать историю

Можно попросить Codex в этом проекте: **«Прочитай последние логи диалога Jarvis
и посмотри, почему он не выполнил команду»**. История не отправляется в чат
автоматически: помощник должен прочитать файл по запросу.

Для чтения без запуска самого Jarvis:

```powershell
Set-Location -LiteralPath 'C:\Users\user\Documents\Jarvis'
& 'C:\Users\user\AppData\Local\Programs\Python\Python310\python.exe' -B jarvis_dialogue.py --last 50
```

Выбор дня и поиск по тексту:

```powershell
& 'C:\Users\user\AppData\Local\Programs\Python\Python310\python.exe' -B jarvis_dialogue.py --date 2026-09-05 --last 100
& 'C:\Users\user\AppData\Local\Programs\Python\Python310\python.exe' -B jarvis_dialogue.py --contains 'оборудования' --last 20
```

Программа читает JSONL, объединяет сессии по времени и показывает последние
подходящие реплики. Повреждённые или оборванные строки пропускаются. Исходная
история не меняется. Чтение истории не выполняет содержащиеся в ней команды.

## Приватность и границы

Журналы находятся под уже исключённым из Git каталогом `logs/`. Не используйте
`git add -f` для этих файлов и проверяйте текст перед пересылкой. Новая запись
маскирует известные секреты из окружения и распространённые формы ключей,
Bearer-токенов и записей `password=…`; это **не универсальное обезличивание**.
Имена, адреса, содержимое писем и прочитанных файлов могут остаться в ответах.
Журнал не зашифрован: действуют обычные права доступа Windows.

Старые технические `logs/jarvis_*.log` сохраняются отдельно. Их прежний формат,
правила хранения и возможные чувствительные данные этим изменением не очищаются.
Они не импортируются в новую историю автоматически.

С 7 сентября `SESSION_MEMORY` управляет отдельной долговременной памятью диалогов.
Старый архив версии 1 индексируется в фоне, новые обработанные ходы сохраняются
непосредственно в рабочую базу. В модель попадают ограниченный недавний контекст
и найденные по теме выдержки, не весь архив. Подробности и правила приватности —
[DIALOGUE_MEMORY.md](DIALOGUE_MEMORY.md). Журналирование остаётся включённым даже
при отключённой постоянной памяти; оно не является исполнением архивных команд.

После каждой реплики файлы закрываются, но принудительная синхронизация диска
не выполняется. При аварийном завершении во время потока его незавершённый текст
может не сохраниться; при сбое питания возможна потеря последних записей.
Если текстовая копия недоступна, JSONL остаётся основным журналом. При ошибке
записи диагностика сообщает `[DIALOGUE]`, выполнение команд не прерывается.

## Реализация и проверка

`jarvis_dialogue.py` — отдельный потокобезопасный писатель и CLI для чтения.
`jarvis_ui.ui_msg` записывает обычную реплику один раз даже без нативного окна.
Потоковый маршрут в `jarvis.py` сохраняет видимую часть при выходе; старые вызовы
`log_interaction` остаются техническими и не дублируют записи в новом архиве.

`test_dialogue.py` проверяет Unicode и многострочный текст, сутки и перезапуск,
параллельную запись, фильтрацию секретов, ошибки диска, чтение повреждённых строк,
голосовой/текстовый вход, быстрые ответы, завершение и отмену потока. Проверки
используют временные файлы и подменяют звук, сеть и модель.

Итоговый прогон: **15/15 наборов, 774 проверки Python**, включая 22 проверки
нового журнала; дополнительно **26/26 DOM-проверок интерфейса**. CLI проверен
отдельно: русский текст выводится в UTF-8 и отсутствие записей сообщается явно.
На 100 коротких синтетических репликах запись в TXT и JSONL заняла по медиане
0,44 мс, 95-й процентиль — 1,34 мс. Это локальный замер, не гарантия скорости
диска. Тестовые реплики не добавлялись в настоящий архив пользователя.
