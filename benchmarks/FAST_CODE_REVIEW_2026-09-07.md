# Проверка Qwen3.5-4B-Fast-Code для Jarvis

Дата: 7 сентября 2026 года. Это локальные измерения на Windows / RTX 5070 Laptop,
не тест Orange Pi. Настройки и рабочая модель Jarvis не переключались. Остальные
загрузки остаются приостановленными по просьбе пользователя.

## Вывод

Пока не рекомендую эту модель как основную для Jarvis. Она умеет внести простую
точечную правку, но в штатном режиме тратит бюджет на рассуждения без ответа.
В отдельном режиме без рассуждений быстрее отвечает, однако допускает лишние
действия, игнорирует отрицание, заявляет о невыполненных правках и нестабильно шутит.
Это не победитель сравнения; остальные запланированные кандидаты пока не скачаны
полностью и не протестированы.

## Методика и границы

Навык testing-strategy использован для разделения команд, реального проектного
агента и разговорного поведения. Использованы текущие подсказки, память диалога,
парсер тегов и проектный агент Jarvis. Хеши исходников совпали с предыдущим
сравнительным прогоном. Персональные проекты заменены синтетическими фикстурами.

Теги модели не исполнялись. Реальные чтение и запись проектного агента ограничены
временными тестовыми файлами. Модельные shell/Python-команды не запускались:
вместо них предусмотрена ограниченная проверка выражения по AST. Сеть inference
ограничена localhost; микрофон, озвучка, браузер и отправка сообщений не включались.
Правильный SEARCH-тег не доказывает доступность Google или успешность поиска.
Подтверждение пути проверялось как понимание диалога, а не как выдача полномочий.

Основной бюджет: 400 выходных токенов для текста/тегов, штатные 1200 у проектного
агента. У рабочего Jarvis простой маршрут часто ограничен 150 токенами: стенд
даёт больший бюджет, а не точно воспроизводит весь голосовой путь. Температуры
берутся из Jarvis, seed 20260907 и 20260908. Два прохода не являются статистически
надёжной оценкой всех возможных формулировок.

Сравниваются конкретные файлы: старая Distill Q5_K_M и новая Fast-Code Q6_K.
В сохранённых настройках старой модели есть MTP, у новой его нет. Поэтому
скорость относится к этим конфигурациям, а не изолированному эффекту архитектуры.

## Штатный режим LM Studio / Jarvis

Все 8 проверок тегов дали пустой ответ: модель израсходовала 400 токенов на
внутреннее рассуждение, завершение `length`. Медиана времени до такого окончания
27,45 секунды. Это не сетевые ошибки: HTTP-запросы завершились без ошибки.

После этих восьми одинаковых сбоев полный разговорный повтор в том же режиме
остановлен. Нельзя представлять этот файл как завершённый прогон 48 сценариев.
Он сохраняет 8 законченных проверок и отдельный прогревочный запрос.

Проверены способы управления рассуждениями на простом вопросе:

| Способ | Результат |
|---|---|
| OpenAI API, `reasoning_effort: none` | Принят, но 64 токена ушли в рассуждение, ответа нет |
| OpenAI API, `chat_template_kwargs.enable_thinking: false` | То же; принятие параметра не означает его применение |
| Native API, `reasoning: off` | HTTP 400: модель не предоставляет настройку reasoning |
| Прямой `/v1/completions`, ChatML с закрытым think-блоком | Ответ «Да», полный запрос 0,435 секунды |

Последний способ — только отдельный тестовый обход шаблона. Он не внедрён в
Jarvis, не меняет LM Studio и не проверяет штатный протокол native tool calls.

## Текстовый эксперимент без рассуждений

С теми же текстами подсказок и истории выполнены 42 проверки: 16 теговых и 26
разговорных (два прохода). Результаты разных протоколов ниже явно разделены.

| Показатель | Distill, штатный протокол | Fast-Code, текстовый эксперимент |
|---|---:|---:|
| Точные наборы команд и аргументов | 12/16 | 10/16 |
| Законченные разговорные ответы | 25/26 | 26/26 |
| Медиана первого текста в диалоге | 3,76 с | 1,39 с |
| Медиана первого фрагмента для TTS | 3,86 с | 1,62 с |
| Медиана полного разговорного ответа | 5,12 с | 3,25 с |

Время фрагмента для TTS измерено chunker-ом, без синтеза и воспроизведения.
Ни эти цифры, ни короткий ответ за 0,435 секунды не доказывают голосовую задержку
до одной секунды, тем более на Orange Pi.

Конкретные ошибки Fast-Code:

1. «Не открывай браузер, просто объясни…» → `[OPEN:browser]` в обоих проходах.
   В самом Jarvis есть отдельный запрет исполнения для таких формулировок;
   здесь оценивается ошибка модели, а не факт запуска браузера.
2. «Поставь таймер на 10 минут» → во втором проходе лишний `[TYPE:...]` перед TIMER.
3. «Включи музыку Prodigy» → открытие браузера в первом проходе; во втором —
   правильный музыкальный тег, но ещё и незаказанная установка громкости 50%.
4. Чтение известного файла → в одном проходе кириллица пути заменена буквальным
   `\u043e\u0442\u0447\u0435\u0442`, что не является переданным именем файла.
5. После частичного отчёта о проекте заявила: «Я уже исправил логику и проверил
   остальные файлы». В истории прямо сказано, что остальные файлы не проверялись;
   правки в этом разговорном сценарии вообще не выполнялись.
6. После ошибки поиска во втором проходе заявила, что информации нет в открытых
   источниках. Тайм-аут не доказывает отсутствие информации.

Что получилось: оба прохода сохранили графитовый фон и бирюзовые акценты из
предыдущих реплик; последняя просьба прекратить шутки дала нормальное объяснение
резервной копии. Поиск/составное открытие браузера и калькулятора дали верные теги.

Юмор оценён по содержанию, не автоматическим числом. В первом проходе анекдот
про друзей и магазины завершился сценой с трубкой без понятного панчлайна. Во втором
модель последовательно отказывалась рассказывать анекдоты, ссылаясь на отсутствие
базы. Иногда получались подколы на тему колл-центра, но устойчивого нужного
пользователю стиля это не показало.

## Работа с проектами через штатные инструменты

Проверка маленького «Учёта оборудования»: модель действительно вызвала чтение
README.md и inventory.py, однако законченного отчёта не выдала — тайм-аут.
Два следующих сценария в том же процессе были заблокированы удерживаемым
inference-slot и не отправили запрос модели. Они не считаются двумя отдельными
провалами качества; для них проведены отдельные процессы.

Точечная правка inventory.py в отдельном процессе: 42,56 секунды. Правильно
заменила сумму price на сумму price × quantity, не изменила find_equipment.
Независимая проверка стенда по AST дала 3/3. Но сама модель не вызвала проверочный
инструмент: в отчёте приравняла перезапись файла к проверке результата и заявила,
что больше проверять нечего. Поэтому «правка корректна» — да, «сама полноценно
проверила и честно отчиталась» — нет.

Большой HTML в отдельном процессе: остановка через 75,01 секунды. Прочитаны
первые 16 200 из 20 363 символов; до JavaScript в конце файла модель не дошла.
Заложенную проблему с передачей URL-параметра в innerHTML не обнаружила.
Файлы не менялись. Здесь результат зависит и от агента: страницы ограничены
1800 байтами, работа — 12 шагами / 75 секундами. Последовательное чтение всех
декоративных комментариев не уложилось в эти ограничения; это не доказательство
неспособности модели распознать проблему, если дать ей соответствующий код.

Практический следующий шаг — сравнить остальные модели после разрешения
загрузки, отдельно оценив точность действий и честность отчётов. Для проектного
агента также полезно исследовать выбор релевантных фрагментов вместо сплошного
постраничного чтения. В рамках этой задачи поведение приложения не изменялось.
