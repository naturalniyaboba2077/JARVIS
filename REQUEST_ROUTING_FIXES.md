## Текущие параметры

| Параметр | Значение |
|---|---|
| Основной движок | `lmstudio` |
| LM Studio normal/code | `mistralai/ministral-3-3b` |
| API | `http://127.0.0.1:1234/v1` |
| Автозагрузка / GPU / контекст | `on` / `0.7` / `8192` |
| Первый токен: LM Studio / Ollama / облако | 30 / 40 / 9 секунд |
| Бюджет генерации | 24 секунды; сложный поток имеет дополнительный внешний лимит |
| Резерв Ollama | `qwen2.5:3b` |
| Голос | `edge`, `ru-RU-DmitryNeural` |
| Темп / высота | `-5%` / `-10Hz` |

Тайм-аут — максимальное ожидание, а не обязательная задержка. При первичной
проверке Ollama загрузка весов заняла 25,3 секунды: старые 1,5 секунды и даже
12 секунд обрывали её. Повторный запуск с выгруженной моделью был быстрее
благодаря прогретому файловому кэшу. При отказе обеих локальных моделей остаётся
облачный резерв, если настроен ключ; это не строгий офлайн-режим.

Автозагрузка LM Studio работает только для loopback и установленного `lms`.
Она не скачивает отсутствующую модель, не запускает Local Server и не повторяет
загрузку после обычного тайм-аута занятой модели. При запуске самого Jarvis
автозагрузка пока покрыта тестами с заглушками; реальная модель загружена через CLI.

## Голос: приближение, не точная копия

Выбран русский мужской нейросетевой голос с немного более медленным темпом и
пониженной высотой. Пользователь сообщил, что чистого эталона нет. Сходство
с конкретным актёром/дубляжом не подтверждалось; это стилизация.

**Edge требует интернет и передаёт текст для озвучивания сервису Microsoft.**
При его отказе ответ остаётся текстом; движок не подменяет голос посреди фразы.
Для офлайн-озвучивания выберите `piper`; установленный `ruslan` сохранён.
Темп и высота доступны в настройках и входят в ключ кэша, чтобы старые реплики
не звучали иначе. Обе реализации Edge используют одинаковые параметры.
Первичное заполнение облачного кэша выполняется в фоне, не задерживая очередь
команд; при первой ошибке синтеза прогрев прекращается. В локальном режиме
запуск Jarvis также не делает ненужный предварительный запрос к OpenRouter.

Аудиопример: `voice_samples/jarvis-edge-preview.mp3`, 8,9 секунды.
Повторный синтез без микрофона и воспроизведения:

```powershell
Set-Location -LiteralPath 'C:\Users\user\Documents\Jarvis'
& 'C:\Users\user\AppData\Local\Programs\Python\Python310\python.exe' -B jarvis_voice_preview.py --engine edge
```

XTTS оставлен дополнительным вариантом. Исправлены загрузка, кэш эталона и
естественная скорость, но текущий `jarvis_sample.wav` содержит автора ролика,
поэтому XTTS не выбран как итоговый голос. При реализации использованы
[документация XTTS](https://docs.coqui.ai/en/stable/models/xtts.html) и
[документация edge-tts](https://github.com/rany2/edge-tts).

отдельно, не в обычных регрессиях.

## Первая проверка после перезапуска

1. Напишите `что ты умеешь` и посмотрите фактический движок ответа.
2. Напишите `проверь проект Учёт оборудования в папке Документы`. Должен быть
   отчёт с точным путём, а не открытие архива. Сам этот личный проект при ремонте
   Jarvis не запускался и не изменялся.
3. Сначала прослушайте аудиопример. Если тембр не подходит, измените темп/высоту
   или вернитесь к Piper, затем перезапустите приложение.

Исходная личная конфигурация сохранена в `jarvis_config.before-routing-voice.json`.
Это приватная резервная копия: она и аудио исключены из Git. Для отката отдельных
настроек используйте UI; полное восстановление резервной копии заменит также
более поздние изменения настроек, поэтому выполняйте его только при остановленном
приложении и осознанно. Коммит и push в этом этапе не выполнялись.

Маленькая локальная модель и STT могут ошибаться. Неоднозначное поручение должно
уточняться, но проверка не гарантирует правильность любого произвольного действия.
Реальные UI, микрофон, воспроизведение и внешние аккаунты требуют отдельной
проверки после перезапуска; подтверждения отправки не отключались.
