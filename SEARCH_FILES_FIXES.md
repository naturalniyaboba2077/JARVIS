# Веб-поиск, файлы и поиск проектов — 5 сентября 2026

Исправления внесены в рабочую копию `C:\Users\user\Documents\Jarvis`.
Для применения полностью закройте старый Jarvis и запустите `launch_jarvis.bat`
или обычный ярлык. Не оставляйте две копии приложения одновременно.

## Почему не работало

- Веб-поиск принудительно использовал DuckDuckGo и Startpage. На этом ПК первый
  возвращал сброс соединения, второй — пустую выдачу. После этого Jarvis открывал
  Google в браузере, но не получал результаты для ответа внутри приложения.
- `JARVIS_PROJECT_ROOTS=C://` разрешал доступ, но поиск проекта проверял только
  непосредственные дочерние папки. Более того, уточнение «в Документах» исключало
  корень `C:/`, хотя Документы находятся внутри него.
- Имя «учета оборудования» не сопоставлялось с каталогом «Учет оборудования».
- Обычный поиск файлов использовал отдельный фиксированный список каталогов и
  ограничение глубины. «Найди файл» автоматически открывал первое совпадение,
  а ошибка открытия могла подавляться. Имя вроде `код.txt` также могло попасть
  в общий обработчик запуска редактора вместо открытия указанного файла.

Реальный проект найден по адресу `C:\Users\user\Documents\Учет оборудования`.
Его исходники не запускались и не изменялись во время этой работы.
Пользовательская настройка `C://` сохранена; права Windows не менялись.

## Текущее поведение

### Голосовое сопровождение поиска

В работающем приложении перед интернет-поиском и поиском файла/папки Jarvis
произносит **«Начинаю поиск, сэр.»**, затем выполняет поиск и один раз озвучивает
фактический результат. Если ничего не найдено или сервис недоступен, озвучивается
соответствующий ответ об отсутствии результата/ошибке, а не выдуманная информация.
Уточнения, отрицания и отклонённые команды не сопровождаются обещанием начать поиск.

Фраза добавлена в кэш текущего голоса; отдельный запрос к языковой модели для неё
не нужен. Во время поиска интерфейс возвращается из состояния речи в «Ищу…».
«Стоп» во время объявления отменяет запуск поиска; поздний результат отменённого
поиска отбрасывается даже после очистки глобального флага новой командой.

Для поисковых тегов модели (веб, файлы, заметки, Telegram, почта и поиск профиля)
объявление выполняется после проверки всего списка действий, непосредственно
перед соответствующим инструментом. Неопознанная быстрая команда всё ещё может
ожидать выбора инструмента моделью. Фоновая речь таймеров для этого не используется.
Совместимый программный API без озвучки и сами низкоуровневые инструменты остаются
тихими; основной цикл и голосовой модельный маршрут передают `progress_fn=speak`.

План проверки по `engineering:testing-strategy` реализован в
`SearchFeedbackTests` внутри `test_discovery_search.py`:

| Область | Тип проверки и критерий |
|---|---|
| Порядок и отмена | Модульные: объявление раньше инструмента; отмена до/во время объявления; поздний результат не возвращается как успех. |
| Маршрутизация | Интеграционные: основной цикл для веба/файлов и модельный маршрут возвращают результат в озвучку ровно один раз. |
| Границы действий | Регрессии: отклонённые теги не запускают речь/поиск; теги внутри выдачи остаются данными; обычные команды не получают поисковое объявление. |

Сеть, микрофон и воспроизведение в этих тестах подменены. Проверяется вызов
озвучивания и его порядок; физическая слышимость на текущих динамиках не проверялась.

### Интернет

Google и Bing запрашиваются параллельно через установленную библиотеку DDGS.
Поддержка этих поисковых движков описана в [документации DDGS](https://github.com/deedy5/ddgs).
Возвращается первая подходящая выдача: заголовки, выдержки и исходные ссылки.
Это **выдержки из поиска, а не чтение страниц целиком**. Источник информации
не становится командой: теги действий внутри найденного текста не исполняются.

Общий срок ожидания — 18 секунд, отдельно от лимитов разговорной модели.
Интерфейс показывает, что идёт поиск; «стоп» прерывает ожидание. Одновременно
допускается не более двух сетевых работников, включая ещё завершающиеся запросы.
Ошибки и отсутствие результатов сообщаются явно; браузер сам не открывается.

Реальный запрос `gpt astra 6` вернул результаты, включая ссылки на OpenAI.
Последний успешный вызов занял **2,33 секунды**; отдельные предыдущие обращения
к поисковым движкам занимали 12–14 секунд. Это измерения, не гарантия задержки.
Доступность сторонних поисковых сайтов по-прежнему зависит от сети и их ограничений.

### Проекты и файлы

Общие корни берутся из `JARVIS_PROJECT_ROOTS`. В настройках поле называется
«Папки для проектов и файлов». Можно оставить `C:/` или перечислить отдельные
папки через `;`; изменение применяется после перезапуска приложения.

`jarvis_paths.py` отделяет разрешённые корни от начальных точек поиска:

- При широком корне поиск начинает с доступных пользовательских папок и корня,
  затем обходит вложенные каталоги. Уточнение «в Документах» сужает поиск.
- Сопоставление папок учитывает `ё/е`, разделители и некоторые распространённые
  русские окончания: «учёт», «учёта», «учёту». Это не универсальное понимание языка.
- Запись инициалов через точки также учитывается: «Сайт ЕК» сопоставляется с
  «Сайт Е.К» или «Сайт Е. К.». При нескольких таких папках нужен полный путь.
  Для обычных файлов это правило не действует: расширения не угадываются.
- Поиск по имени ограничен 25 000 просмотренных элементов и пятью секундами
  с проверкой лимитов между элементами. Он не читает содержимое файлов.
- Для выбора конкретного объекта используется первый уровень обхода с точными
  или нормализованными совпадениями. Несколько совпадений на этом уровне требуют
  полного пути; глобальная уникальность имени на всём диске не утверждается.
- Имена уже перечисленных папок одного уровня проверяются до обхода их
  содержимого: крупная соседняя папка не расходует бюджет раньше выбора известного
  имени. Лимиты времени, отмена и проверка ссылок сохраняются.
- Если достигнут лимит, Jarvis сообщает об ограниченном поиске. Полный путь
  обходит поиск по имени, но не проверку принадлежности разрешённым корням.
- Автоматический обход пропускает служебные каталоги Windows, AppData, ProgramData,
  `.git`, зависимости и кэши. Это исключения поиска, а не дополнительный запрет
  на явно указанный полный путь внутри разрешённых корней. Ссылки и reparse points
  не используются; системные права доступа Windows сохраняются.

`jarvis_local_files.py` разделяет четыре действия:

| Команда | Результат |
|---|---|
| `найди файл имя.txt` | Возвращает найденные полные пути, ничего не открывая. |
| `открой файл имя.txt` | Выбирает конкретный файл и передаёт ОС команду открытия; ошибка не называется успехом. |
| `прочитай файл имя.txt` | Читает текст с диска, не исполняя его как код или команды. |
| `покажи содержимое папки документы` | Показывает до 100 имён элементов без открытия Проводника. |

Можно указать полный путь в кавычках или уточнить «в документах» / «в загрузках».
Для открытия и чтения по имени требуется полное имя с расширением; расширение
не угадывается. Текстовое чтение ограничено 300 000 байтами и предпросмотром
8 000 символов, поддерживает UTF-8 и CP1251. Это не универсальный читатель
PDF, DOCX, изображений или произвольных бинарных файлов.

Новые теги: `[FILE:READ:имя или полный путь]` и `[FILE:LIST:папка]`.
Они зарегистрированы в парсере и исполнителе. Параметризованные локальные команды
обрабатываются с сохранением указанного пути, отдельно от статических
`INTENT_PATTERNS` запуска приложений. Текст файлов не парсится повторно как действие.
Произвольные запись, переименование, перемещение и удаление файлов этим модулем
не добавлены; версионируемые изменения проекта остаются в проектном агенте.

### Команды проектному агенту

Для обзора:

```text
проверь проект учета оборудования в документах
```

Правильная команда `проведи рефакторинг проекта учета оборудования в документах`
теперь распознаётся как разрешение на изменение. В этой работе она проверялась
только на уровне разбора команды — рефакторинг личного проекта не выполнялся.

Искажённое распознавание «проведили факторинг…» вызывает уточнение о рефакторинге,
а не угадывание опасного действия. Указание папки перед двоеточием с задачей также
не включается ошибочно в имя проекта.

Режим «проверь» остаётся чтением и статической проверкой, без записи и host-shell.
Явные поручения изменить проект сохраняют прежний режим работы. Корни файлового
поиска не являются ограничением для всех возможностей shell и не дают права администратора.

## Проверка

- Регрессии запускаются через `run_tests.py` в копии исходников, без личных
  данных и внешней сети. Новый `test_discovery_search.py` проверяет поиск,
  ограничения корней, неоднозначность, отмену, файловые команды и отказы поиска.
- Итоговый прогон после голосового сопровождения: **14 из 14 наборов, 751 проверка
  Python**, включая 46 проверок поиска и файлов (11 — порядок озвучки и отмена).
  `git diff --check` не выявил ошибок
  пробелов; Git сообщает только об имеющихся преобразованиях CRLF/LF.
- DOM-проверки: 26 из 26. Это проверка логики интерфейса, не визуальный осмотр окна.
- Дополнительно выбранная локальная модель LM Studio работала с синтетическим
  проектом в временной папке: вызвала `list_files`, затем `read_file`, объяснила
  деление на ноль в тестовом `app.py`. Проверены неизменность файла и отсутствие
  запуска команд; режим — обзор. Полный разбор занял **29,95 секунды**.
- Ни микрофон, ни реальные динамики, ни код личного «Учет оборудования» в этом
  интеграционном тесте не использовались. Облачная модель не требовалась.

Изменения не гарантируют безошибочное понимание любого поручения малой локальной
моделью. Для оставшегося сбоя нужны точный текст команды, ответ и выбранный путь.
