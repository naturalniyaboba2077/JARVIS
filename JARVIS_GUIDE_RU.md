**Точка входа:** `jarvis.py`

## 1. Что такое Jarvis

Обновление 6 сентября: [продолжение разговора на 60 секунд, обращение «Джарвис»,
исправления STT/поиска проектов и новая строка выполнения задач](CONVERSATION_UX.md).
Там же описаны новые настройки, ограничения определения адресата и проверка UI.

Jarvis — русскоязычный голосовой помощник для Windows. Он принимает команды с микрофона или из текстового поля собственного окна, отвечает голосом и выполняет действия на компьютере.

Простые команды обрабатываются локальными функциями без обращения к языковой модели. Для разговоров и сложных запросов используется LM Studio, Ollama либо OpenRouter. На этом ПК выбран LM Studio. «Работает локально» не означает обязательного отсутствия сетевых запросов: облачный резерв и отдельные интеграции могут использовать интернет.

Основные возможности:

- Открытие приложений и сайтов, управление громкостью, воспроизведением и некоторыми функциями окон Windows.
- Скриншоты, буфер обмена, поиск файлов и открытие последней загрузки; OCR при наличии соответствующих зависимостей.
- Таймеры, напоминания, список дел, дата, время, погода и веб-поиск.
- Личная память и Markdown-заметки в Obsidian.
- Чтение, поиск и экспорт сообщений Telegram после подключения личного аккаунта.
- Работа с Gmail и Google Calendar после OAuth-авторизации; отправка сообщений и писем через стадию подтверждения.
- Проектный агент: чтение и версионируемые правки файлов в разрешённых каталогах, просмотр истории и отмена последней правки.

Отправка письма или сообщения требует подтверждения конкретного подготовленного запроса; срок ожидания — 120 секунд. Перед отправкой проверьте получателя и текст.

## 2. Быстрый запуск на этом ПК

Откройте PowerShell. Следующие команды используют уже найденный рабочий Python 3.10, а не случайный `python` из `PATH`:

```powershell
Set-Location -LiteralPath 'C:\Users\user\Documents\Jarvis'
$jarvisPython = 'C:\Users\user\AppData\Local\Programs\Python\Python310\python.exe'
& $jarvisPython --version
& $jarvisPython -B health_check.py
```

Просмотрите весь вывод проверки: строки `MISS` и `FAIL` требуют внимания. Итоговая фраза `Environment looks ready` и нулевой код этой проверки сами по себе не подтверждают исправность конфигурации, доступность облака, микрофона или OAuth.

Затем запустите приложение в том же окне PowerShell:

```powershell
& $jarvisPython jarvis.py
```

Дождитесь калибровки микрофона и сообщения об ожидании команды. Первое подключение моделей может занимать больше времени, чем последующие запуски.

Для первой проверки произнесите: **«Джарвис, который час»**. В текстовом поле окна можно написать `который час` без обращения по имени. Для диагностики произнесите **«Джарвис, проверь системы»**.

Другие способы запуска:

- `launch_jarvis.bat` в папке проекта — запуск с видимой консолью для диагностики.
- Ярлык `J.A.R.V.I.S.` на рабочем столе, если он установлен, — запуск через `pythonw.exe` без консоли. Скрипт `install_shortcut.ps1` создаёт или обновляет этот ярлык; для обычного запуска выполнять его каждый раз не нужно.

Не запускайте несколько копий одновременно: они могут конкурировать за микрофон и файлы состояния. Начинайте с обычных прав пользователя, не от имени администратора.

**Про окружение:** существующая здесь `.venv` создана на другом Python и не содержит всех зависимостей. Она не является рабочей средой этого приложения. Не используйте её для запуска или оценки тестов и не удаляйте автоматически.

### Остановка и выход

- `Джарвис, стоп` или `стоп` в текстовом поле — запрос прерывания текущего ответа/выполнения, а не откат уже сделанных действий.
- `выход` в текстовом поле — завершение основного цикла; если окно остаётся открытым, закройте его кнопкой закрытия.
- Закрытие окна приложения также запрашивает остановку.

Команда `стоп` не заменяет отмену ожидающей отправки письма или сообщения. Для отмены отправки используйте `отмена` и проверьте ответ; подробнее в разделе 8.

## 3. Установка и настройка

### Если переносите проект на другой Windows-ПК

Проверенная здесь среда — Python 3.10 на Windows. Микрофон и устройство вывода нужны даже при наличии текстового интерфейса: основной цикл инициализирует аудио при старте.

1. Перенесите исходники нужной версии. Этот документ описывает ветку `codex/fix-audit-findings`; другая ветка может содержать более старый код.
2. Выберите Python для приложения и используйте один и тот же интерпретатор для установки зависимостей, тестов и запуска.
3. Установите зависимости из `requirements.txt` в выбранное окружение. В нём есть Windows- и CUDA-ориентированные пакеты: это не готовый универсальный список для Linux/ARM.
4. Создайте личную конфигурацию из примера, только если её ещё нет, и заполните необходимые настройки.
5. Подготовьте выбранные движки и модели, выполните `health_check.py`, затем запустите приложение из корня проекта.

Команда установки для текущего ПК, если действительно требуется восстановление зависимостей, в PowerShell из раздела 2:

```powershell
& $jarvisPython -m pip install -r requirements.txt
```

Не переустанавливайте всё при каждом запуске. Список зависимостей не является точным lock-файлом: свежая установка может получить другие версии библиотек и требует повторной проверки.

### Конфигурация

Основной файл — `jarvis_config.json` рядом с `jarvis.py`. Образец — [jarvis_config.example.json](jarvis_config.example.json). Не заменяйте существующий личный конфиг образцом: потеряются настройки и ключи.

Безопасное первоначальное копирование из корня проекта:

```powershell
if (-not (Test-Path -LiteralPath '.\jarvis_config.json')) {
    Copy-Item -LiteralPath '.\jarvis_config.example.json' -Destination '.\jarvis_config.json'
}
```

Параметры можно менять в настройках окна или редактированием JSON при остановленном приложении. После изменения движка, модели или микрофона перезапустите Jarvis. **Переменные окружения имеют приоритет над JSON**: если параметр словно игнорируется, проверьте старые переменные окружения и способ запуска.

| Параметр | Назначение |
|---|---|
| `JARVIS_LLM` | Режим ответов: `lmstudio`, `local` (Ollama) или `cloud`; возможны резервные маршруты. |
| `LM_STUDIO_MODEL`, `LM_STUDIO_CODE_MODEL` | Локальные модели обычных и сложных запросов; на этом ПК обе — `mistralai/ministral-3-3b`. |
| `LM_STUDIO_AUTOLOAD`, `LM_STUDIO_GPU`, `LM_STUDIO_CONTEXT` | Автозагрузка через `lms` при работающем локальном сервере, доля GPU и контекст. |
| `OLLAMA_MODEL` | Имя установленной локальной модели; в образце — `qwen2.5:3b`. |
| `OPENROUTER_API_KEY` | Личный ключ облачного провайдера. Значение-заглушка из примера не работает. |
| `OPENROUTER_MODEL`, `OPENROUTER_FREE_MODEL` | Основная и резервная облачные модели. Их доступность определяется провайдером, а не кодом Jarvis. |
| `STT_ENGINE`, `WHISPER_MODEL` | Распознавание речи: `whisper` или `google`; размер локальной модели в образце — `small`. |
| `TTS_ENGINE` | Озвучивание: `auto`, `piper`, `edge` или дополнительный тяжёлый вариант `xtts`. |
| `PIPER_VOICE`, `EDGE_VOICE` | Голос выбранного синтезатора. Для Piper нужны локальные файлы голоса. |
| `EDGE_RATE`, `EDGE_PITCH` | Базовые темп и высота Edge: `-5%` и `-10Hz`. Профиль подачи корректирует их. Синтез облачный; это приближение, не точный киношный голос. |
| `JARVIS_VOICE_STYLE` | `lively` — живой, `calm` — спокойный, `neutral` — нейтральный. Настройки → Основные → Подача голоса. Профиль влияет на темп Piper и темп/высоту Edge; характер XTTS берётся из образца. |
| `JARVIS_MIC_INDEX` | Индекс микрофона из списка устройств, который приложение показывает при запуске. |
| `JARVIS_PAUSE_THRESHOLD` | Пауза, после которой фраза считается завершённой; в образце — `1.0` секунды. Если длинные команды обрываются на паузах, увеличьте её в Дополнительно → Время ожидания. |
| `JARVIS_FOLLOWUP_WINDOW`, `JARVIS_FOLLOWUP_MODE` | Окно продолжения разговора и фильтрация речи без повторного обращения. |
| `SESSION_MEMORY` | Сохранение краткой истории диалога между запусками; по умолчанию выключено. |
| `JARVIS_PROJECT_ROOTS` | Разрешённые каталоги проектов и локальных файлов, перечисленные через `;`. Вложенные папки участвуют в ограниченном поиске. |
| `OPENROUTER_AGENT_MODEL` | Модель проектного агента только в облачном режиме. В локальных режимах используется выбранный локальный сервер. |

### Выбор движков

Локальный набор — Ollama + faster-whisper + Piper. Ollama устанавливается отдельно от Python-зависимостей; модель для него должна быть загружена. Piper использует пару файлов `.onnx` и `.onnx.json` в `piper_models`. Подготовка описана в [SETUP_INSTRUCTIONS.md](SETUP_INSTRUCTIONS.md).

Облачный набор — OpenRouter для ответов, Google для распознавания, Edge TTS для озвучивания. Для него нужны интернет и соответствующие настройки; Python-зависимости приложения всё равно требуются.

`TTS_ENGINE=auto` выбирает доступный движок; выбор фиксируется на один ответ. `JARVIS_LLM=local` не гарантирует строгий офлайн: облачные резервы, поиск, погода, Telegram и Google-интеграции могут обращаться в сеть.

### Дополнительные интеграции

- **Telegram:** задайте `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` и `TELEGRAM_PHONE`, затем пройдите вход в интерфейсе. Код входа и пароль 2FA вводите только в процессе авторизации. Для отправки отчётов ботом отдельно нужны `TELEGRAM_REPORT_BOT_TOKEN` и явно указанный `TELEGRAM_REPORT_CHAT_ID`.
- **Google:** `credentials.json` содержит OAuth-настройки; после авторизации появляется `token.json`. Это личные файлы, не исходники. При проблемах с правами проверьте выданные разрешения и пройдите повторную авторизацию по инструкции настройки.
- **Obsidian:** код ищет хранилище `Obsidian Vault` в заданных в `jarvis_notes.py` расположениях, в том числе рядом с папкой проекта. Заметки Jarvis помещаются в `Jarvis DB` внутри хранилища. На другом ПК расположение нужно проверить отдельно.
- **OCR:** кроме Python-пакета нужен установленный Tesseract. Наличие пункта в интерфейсе не подтверждает готовность внешней программы.

## 4. Как пользоваться

Для голосового ввода начинайте с «Джарвис». Можно сначала произнести имя, затем команду в открывшемся окне ожидания. Горячая клавиша `Ctrl+Alt+J` открывает окно голосового ввода без имени, если системная регистрация сочетания сработала.

В таблице фразы приведены для текстового поля; при голосовом вводе добавляйте обращение.

| Пример команды | Что делает |
|---|---|
| `открой браузер` | Открывает браузер. |
| `который час` | Сообщает местное время компьютера. |
| `какая погода в Москве` | Запрашивает погоду; нужен интернет. |
| `поставь таймер на 10 минут` | Запускает таймер в работающем приложении. |
| `добавь задачу проверить документацию` | Добавляет пункт в список дел. |
| `покажи список дел` | Показывает/озвучивает задачи. |
| `напомни в 18:30 купить молоко` | Создаёт напоминание. Для срабатывания помощник должен работать. |
| `сделай скриншот` | Сохраняет снимок экрана. |
| `громкость 30` | Устанавливает системную громкость. |
| `следующий трек` | Отправляет медиакоманду активному проигрывателю. |
| `покажи мои чаты в телеграме` | Показывает чаты после авторизации Telegram. |
| `проверь почту` | Читает непрочитанные письма после авторизации Google. |
| `проверь системы` | Выводит диагностику Jarvis и выбранных движков. |
| `найди в интернете информацию о Python` | Возвращает выдержки из поисковой выдачи со ссылками. |
| `найди файл имя.txt` | Ищет файл без автоматического открытия. |
| `прочитай файл имя.txt` | Читает обычный текстовый файл; код и теги внутри не исполняются. |
| `покажи содержимое папки документы` | Показывает имена файлов и папок без открытия Проводника. |

Формулируйте команды явно. Обсуждение «что будет, если попросить…» не должно выполнять действие; для этого есть проверка намерения, но она эвристическая. Проверяйте результат важной операции в соответствующем приложении, а не только по голосовому ответу.

## 5. Архитектура

Основной поток обработки:

```text
Микрофон → распознавание речи → проверка обращения ─┐
                                                 ├→ очередь команд
Текстовое поле окна ──────────────────────────────┘
       → обработка подтверждения / быстрый обработчик / языковая модель
       → проверка списка действий → вызов инструментов
       → результат в интерфейсе и голосовой ответ
```

| Область | Файлы и ответственность |
|---|---|
| Ядро | `jarvis.py`: запуск, очередь, маршрутизация, системный промпт, связь с интерфейсом. |
| Конфиг и состояние | `jarvis_config.py`, `jarvis_state.py`: параметры, общее состояние, отмена и метрики. |
| Голос и модели | `jarvis_stt.py`, `jarvis_llm.py`, `jarvis_tts.py`: распознавание, генерация ответа и озвучивание. |
| Действия на ПК | `jarvis_actions.py`, `jarvis_tools.py`, `jarvis_features.py`, `jarvis_apps.py`, `jarvis_platform.py`: разбор команд, инструменты и платформенные операции. |
| Данные и сервисы | `jarvis_store.py`, `jarvis_notes.py`, `jarvis_telegram.py`, `jarvis_mail.py`, `jarvis_lookup.py`: память, заметки и внешние интеграции. |
| Работа с проектами | `project_agent.py`, `jarvis_fileops.py`, `jarvis_project_checks.py`: ограниченный агент, журнал правок, восстановление и проверки синтаксиса. |
| Поиск и чтение файлов | `jarvis_paths.py`, `jarvis_local_files.py`: общие корни доступа, ограниченный рекурсивный поиск, открытие конкретного файла, чтение текста и список папки. |
| Интерфейс и журнал | `jarvis_ui.py`, `ui/index.html`, `overlay.py`, `jarvis_log.py`: окно, визуализация и логи. |

Важные решения реализации:

- Конфигурация загружается раньше модулей, читающих переменные окружения.
- Микрофон обслуживает один фоновый слушатель. Текстовый интерфейс ставит команды в общую очередь; он не отправляет письма напрямую из своего потока.
- Ответ модели целиком проверяется перед выполнением содержащихся в нём действий. Результат инструмента не разбирается повторно как новая команда.
- Ответы, способные вызвать действие, буферизуются до проверки и выполнения; обычный разговор может озвучиваться потоково.
- Отмена привязана к конкретному запуску речевого конвейера, чтобы новый запрос не возобновлял старый отменённый ответ.

Архитектура модульная, но разделение не завершено: `jarvis.py` остаётся крупным модулем, несколько слоёв маршрутизации пересекаются, используются импорты `*`. Это направления дальнейшего рефакторинга, а не отдельный новый функционал.

## 6. Проектный агент, данные и безопасность

### Работа с файлами проектов

При проверке Jarvis сначала озвучивает начало работы и показывает текущий
этап. Большие исходники передаются модели страницами; при лимите или повторах
возвращается частичный отчёт с фактическими действиями и тем, что осталось.
Подробности и проверки: [PROJECT_AGENT_FIXES.md](PROJECT_AGENT_FIXES.md).

Проектный агент использует выбранный движок: LM Studio, Ollama или OpenRouter. В первых двух случаях облачный ключ не нужен. Задавайте `JARVIS_PROJECT_ROOTS` как конкретные нужные папки; весь `Documents` или `Desktop` предоставляет более широкий доступ. Ограничение корней агента не ограничивает все возможности shell.

Примеры команд для уже настроенного разрешённого проекта:

```text
проверь проект Учёт оборудования в папке Документы
проверь проект ИмяПроекта и исправь ошибки
поработай над проектом ИмяПроекта: исправь опечатку в README
покажи правки в проекте ИмяПроекта
отмени последнюю правку в проекте ИмяПроекта
```

Правки проходят через журнал файловых операций. Перед отменой проверяется состояние файла; конфликт с последующей ручной правкой может привести к отказу в откате. Это защита данных, а не повод принудительно перезаписывать файл. История не заменяет Git и резервную копию; не редактируйте её вручную.

**Обзор (`проверь проект …`) разрешает чтение и статическую проверку, но не запись и host-shell.** Компиляция Python в памяти не является запуском тестов. При явном поручении изменить проект или запустить команды включается режим работы: доступны версионируемая запись и shell на хосте. Изменения через shell не попадают в файловый undo. Проверяйте команды и фактический результат; это не песочница.

Название проекта сопоставляется с реальными каталогами с учётом `ё/е`, разделителей и распространённых окончаний («учёт/учёта»). Несколько совпадений на первом подходящем уровне поиска требуют полного пути. Поиск ограничен по времени и числу элементов; доступ к `C:/` не означает полную индексацию диска. Неразборчивая команда вроде «травей … проекта …» или «проведили факторинг…» вызывает уточнение, а не открытие произвольного файла из загрузок. Подробности и ограничения — в [SEARCH_FILES_FIXES.md](SEARCH_FILES_FIXES.md).

### Границы защиты

Обычные инструменты `[CMD:...]` и `[EXECUTE_PYTHON]` вне проектного агента могут выполнять команды с правами пользователя. Антиудалительные проверки — эвристики, **не песочница**. Нельзя обещать, что Jarvis не сможет повредить пользовательские файлы или что каждое действие потребует отдельного подтверждения.

Отмена не возвращает уже отправленное сообщение и не откатывает произвольную системную команду. Некоторые блокирующие вызовы аудио/синтеза нельзя мгновенно остановить внутри библиотеки: поздний результат отбрасывается, но нативный вызов может завершиться позже.

### Что хранится локально и что нельзя публиковать

- `jarvis_config.json` и его резервные копии — настройки и ключи.
- `credentials.json`, `token.json`, `telegram_data/` — авторизация и сессии.
- Файлы памяти, задач, напоминаний и истории диалога — личные данные.
- `logs/`, `file_history/`, экспорты переписок, скриншоты и аудиозаписи — потенциально чувствительное содержимое.
- `piper_models/` и кэши — локальные ресурсы, обычно не нужные в Git.

При облачном ответе текст запроса и добавленный контекст памяти могут передаваться провайдеру модели. Облачное распознавание получает аудио, облачное озвучивание — текст ответа. Поэтому локальное хранение заметок не означает, что их содержимое никогда не покидает ПК.

Перед публикацией проверяйте `git status`, список добавленных файлов и diff. Не добавляйте личные файлы через `git add -f`. Не прикладывайте необработанные логи к публичным отчётам об ошибках.

## 7. Проверки и порядок разработки

Полный набор тестов запускайте через общий runner, используя тот же Python, что и приложение:

```powershell
Set-Location -LiteralPath 'C:\Users\user\Documents\Jarvis'
& 'C:\Users\user\AppData\Local\Programs\Python\Python310\python.exe' -u -B run_tests.py
$jarvisTestExitCode = $LASTEXITCODE
Write-Output "Код завершения тестов: $jarvisTestExitCode"
```

`run_tests.py` создаёт временную копию исходников без личных файлов, подменяет буфер обмена и блокирует внешние socket-подключения тестовых процессов. Это изоляция доверенных регрессионных тестов, не среда для запуска произвольного враждебного кода. Не запускайте старые тестовые файлы напрямую рядом с реальными пользовательскими данными.

Коды runner: `0` — выбранные наборы прошли, `1` — есть провал или тайм-аут, `2` — неизвестное имя набора. Внешняя оболочка должна передавать этот код, если тесты используются в автоматизации.

Актуальные результаты и отдельные проверки реальных моделей приведены в [REQUEST_ROUTING_FIXES.md](REQUEST_ROUTING_FIXES.md). Успешные регрессии не означают отсутствия багов. Микрофон, воспроизведение через колонки, интерфейс после перезапуска и внешние аккаунты требуют отдельной ручной проверки.

Рекомендуемый цикл изменения проекта:

1. Прочитать актуальный `AGENTS.md`, если он есть локально, и связанные с задачей исходники.
2. Проверить `git status`; сохранить чужие и незавершённые изменения.
3. Для исправляемого дефекта добавить воспроизводимый тест, затем внести минимальную правку.
4. Запустить общий runner; отдельно проверить затронутый реальный сценарий без нежелательных отправок или действий.
5. Проверить diff и отсутствие секретов. Коммит и публикацию выполнять как отдельный согласованный шаг.

## 8. Известные ограничения и устранение проблем

### Подтверждение почты и Telegram

Точка и пунктуация на краях ответа нормализуются: `подтверждаю.` и `отмена.` распознаются. Ожидание истекает через 120 секунд; состояние снимается под общей блокировкой до сетевого вызова. Устаревшая кнопка не подтверждает новый запрос.

Чтобы отменить подготовленную отправку, введите `отмена` и дождитесь подтверждения отмены. Не проверяйте отмену словом `да`: это разрешение на отправку. Если сетевой сервис дал неопределённый результат, проверьте исходящие перед повтором — блокировка не даёт гарантии exactly-once на стороне внешнего провайдера.

Сценарии пунктуации, срока ожидания и конкурентного подтверждения покрыты регрессионными тестами. Реальные письма и сообщения во время проверки не отправлялись.

### Другие частые ситуации

| Симптом | Что проверить |
|---|---|
| `ModuleNotFoundError`, часть тестов падает | Путь к интерпретатору. На этом ПК используйте Python 3.10 из раздела 2, не существующую `.venv`. |
| Jarvis не слышит или выбирает не тот вход | Разрешение Windows на микрофон, список устройств при старте, `JARVIS_MIC_INDEX`, отсутствие второй копии приложения. |
| Ответ обрывается во время паузы пользователя | `JARVIS_PAUSE_THRESHOLD`, `JARVIS_PHRASE_TIME_LIMIT` и качество распознавания. Не уменьшайте модель Whisper вслепую. |
| Нет голоса | Устройство вывода, выбранный TTS, файлы модели Piper либо сеть для Edge; проверьте консоль. |
| Нет ответа от модели | Доступность выбранного сервера, правильный ID и загрузку модели. Причины отказа каждого резерва теперь показываются в ответе. |
| Настройки не применяются | Нажмите «Применить» и проверьте статус: активный ответ/прогрев или подтверждение Telegram могут задерживать применение. Проверьте переменные окружения и JSON. Перезапуск для параметров панели больше не требуется; подробности в [LIVE_SETTINGS.md](LIVE_SETTINGS.md). |
| Диагностика сообщает о недоступной Ollama в облачном режиме | Сводка проверяет локальный сервис независимо от выбранного основного режима; это не равнозначно отказу облачного ответа. |
| Долгоживущий процесс пишет в старый лог | Имя лог-файла вычисляется при старте. Ежедневная автоматическая ротация и ограничение размера пока не реализованы. |

Также в коде есть невызванная функция ежедневного приветствия: автоматическую утреннюю сводку нельзя считать подключённой. Локальный `custom_patch.py` — устаревший вспомогательный файл, не штатная точка входа. Существующую `.venv`, этот файл и историю Git не следует удалять ради «очистки» без отдельной проверки и резервирования.

## 9. Направления дальнейшего развития

Ближайший полезный порядок работ:

1. Расширение проверок естественных поручений и точности аргументов инструментов; общий механизм подтверждений уже подключён.
2. Ротация логов и воспроизводимая документированная среда установки.
3. Упрощение маршрутизации, явные импорты и вынесение промпта из ядра без потери быстрых локальных команд.
4. Разделение подтверждённых на реальном оборудовании возможностей и проверок с заглушками.

Отдельный аппаратный этап — Orange Pi 5 Pro с 8 ГБ RAM, microSD 32 ГБ и небольшим вентилятором. Доступ к плате отложен владельцем; установка ОС, SSH-подключение и реальный запуск Jarvis на ARM пока не выполнены. Наличие слоя переносимости не означает готовность Windows-функций к Linux.

Домашний сервер, Home Assistant, голосовые точки и офлайн-база знаний — направления дальнейшего плана, а не уже установленная часть текущего Windows-приложения.
