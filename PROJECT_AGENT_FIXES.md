# Проектный агент: контекст, прогресс и частичный отчёт

Изменения от 6 сентября 2026 года. Относятся к командам «проверь проект …»
и к явно порученной работе над проектом, а не к обычному разговорному стримингу.

## Что было причиной молчания

В наблюдавшемся запуске агент передавал файлы целиком и накапливал историю:
запрос вырос до 48 138 токенов при доступном контексте примерно 20 тысяч.
Модель повторно запрашивала файлы, а после 12 шагов приложение возвращало
общую фразу о лимите вместо отчёта. Голос включался только после всего цикла.

## Как работает теперь

- Живые голосовой и текстовый маршруты сначала озвучивают «Начинаю проверку
  проекта, сэр.» либо «Начинаю работу с проектом, сэр.». Эти фразы входят в
  кэш голоса. Начало не зависит от ответа модели, но фактическая задержка
  звука зависит от готовности выбранного TTS/аудиоустройства.
- Интерфейс показывает поиск проекта, текущий шаг, чтение файла, поиск в
  исходниках и составление отчёта. Каждый файл отдельно не озвучивается.
- `read_file` принимает `path`, `offset`, `limit`. **Смещение и размер —
  символы, не строки.** Ответ содержит `next_offset`, номера строк, общий
  размер в символах, SHA-256 и страницу. `next_offset=null` означает конец.
  До 1800 байт UTF-8 исходного текста и до 2400 байт JSON на страницу;
  экранирование может уменьшить фактическую страницу.
- Чтение диска по-прежнему использует защищённый снимок `jarvis_fileops`
  с проверкой ссылок/изменения файла. Снимок ограничен 8 МиБ; целиком в
  модель он не передаётся. Это порционное чтение для модели, не потоковый
  дисковый reader произвольно больших файлов.
- `jarvis_agent_context.py` читает размер **загруженного экземпляра** LM Studio
  через локальный `/api/v1/models` (до 2 секунд на сетевое ожидание), не меняя
  загрузку модели. Максимальная ёмкость из карточки модели не используется.
  Нет перехода на удалённые адреса, прокси или HTTP-редиректы. Если эти метаданные
  недоступны, используется `LM_STUDIO_CONTEXT` (по умолчанию 8192).
- Сериализованные сообщения вместе со схемами инструментов ограничены бюджетом:
  для загруженного контекста 20 000 — 18 200 байт UTF-8, для 8192 — 6392,
  с запасом на выход/шаблон и верхней границей 24 000 байт. Это консервативная
  оценка, не точный токенизатор. Резервная настройка не должна превышать
  реально загруженный контекст, особенно на других OpenAI-совместимых серверах.
- Исходное поручение не обрезается. Старые полные обмены assistant/tool
  удаляются совместно; не остаются осиротевшие ID инструментов. Ограниченный
  журнал сохраняет выполненные операции и последние смещения, а не скрытые
  рассуждения модели. Сокращённый журнал не является полной памятью о коде.
- Одинаковая страница не читается снова из-за другой записи того же пути
  или размера страницы. После двух шагов с повторами/ошибками без прогресса
  агент переходит к частичному отчёту. После записи/команды разрешается
  обновить наблюдения; одинаковая команда не повторяется автоматически.
- Полная замена существующего файла через агентский `write_file` требует,
  чтобы в этом запуске были прочитаны все его страницы без пробелов в диапазоне.
  Перед записью проверяется хеш прочитанного снимка. Непрочитанный остаток не
  должен пропасть из-за того, что модель приняла фрагмент за целый файл.
  Новые файлы создавать можно; политика явно разрешённого host shell прежняя.
- При лимите шагов, времени, пустом ответе или ошибке запроса делается одна
  попытка получить частичный отчёт **без права вызывать инструменты**.
  Даже если эта попытка не удалась, приложение возвращает фактический журнал,
  причину остановки и сведения о незавершённой проверке. Ошибка поставщика
  не копируется целиком в ответ — она может содержать секреты.

## Лимиты и отмена

До 12 шагов и до 4 вызовов на шаг. Рабочий бюджет цикла — 75 секунд;
на финальную сводку выделяется ещё до 20 секунд, на один запрос — до 30.
Это не гарантия общего времени всей команды: поиск проекта, TTS и уже
начавшиеся файловые/host-shell операции имеют отдельные ограничения.

Ожидание модели прерывается по «Стоп». Поздний ответ может только завершить
сетевой worker, но не запустить инструменты. Незавершённый запрос удерживает
единственный слот проектного inference до своего фактического завершения;
отмена не создаёт неограниченное число фоновых запросов. Команда, уже
исполняемая host shell в режиме изменений, сохраняет прежний лимит 120 секунд.

Обзор остаётся без записи и без запуска кода приложения. Чтение страницы
не называется тестированием. Изменения через `write_file` версионируются;
произвольные изменения shell не попадают в undo. Результаты инструментов
не передаются в парсер тегов действий. Финальная сводка — не новая команда.

## Проверка

Изолированные регрессии:

```powershell
python -B run_tests.py test_agent_runtime.py test_request_routing.py test_audit_fileops.py
python -B run_tests.py
```

Отдельный opt-in тест с настоящей выбранной моделью LM Studio:

```powershell
python -B jarvis_agent_smoke.py
python -B jarvis_agent_smoke.py --partial
```

Он создаёт временный искусственный файл 232 536 байт, проверяет функцию
деления в его начале и удаляет фикстуру при выходе. Не читает личные проекты,
не запускает их код, микрофон, динамики, shell или облачный резерв.
На `qwen3.8-4b-distill` обычный сценарий дал находку `ZeroDivisionError`
за 24,43 секунды; принудительный частичный отчёт после одного шага — за
14,60 секунды. Это измерения конкретных запусков, не обещание времени аудита.
Повторный прогон частичного отчёта на итоговом коде с определением загруженного
контекста завершился за 7,29 секунды. Итоговая регрессия: 16/16 наборов Python,
в том числе 39 новых тестов агента, и 26/26 DOM-проверок интерфейса.

После обновления Python-файлов нужно перезапустить Jarvis. Настройку модели
и разрешённые папки эти изменения не меняют. Автоматического продолжения
агента после перезапуска нет; следующий запрос — новая задача.

## Контекст и подтверждение выполнения — 7 сентября, второй раунд

`jarvis_agent_context` сохраняет полезные результаты чтения приоритетнее пустой
страницы EOF или повторного списка. Перед удалением полезного снимка уменьшается
служебный журнал. Лимит по-прежнему 6392 UTF-8 байта при контексте 8192, включая
инструкции и схемы; это не хранение всего проекта в окне модели. Полный журнал
для итогового отчёта не сокращается. Исходное поручение и пары tool-call ID
сохраняются; память не превращает файловый текст в инструкции.

Повторное чтение возвращает кэш страницы без повторного файлового I/O, но не
считается прогрессом. Перед возможной записью инвалидируется прежний снимок
целевого файла, в том числе при последующей ошибке инструмента. Снимки других
файлов сохраняются. Host shell потенциально меняет любые файлы проекта, поэтому
инвалидирует все наблюдения и покрытие чтения. Проверка синтаксиса этого не делает.

`jarvis_agent_evidence` отделяет факты выполнения от текста модели. Успешный
`write_file` подтверждается чтением точных байтов и хешем. Отчёт перечисляет
фактические записи и реальные результаты команд; проверка до последней записи
не выдаётся за проверку после неё. Неудачная попытка изменения тоже сбрасывает
достоверность прежней проверки. `compile` обозначается как синтаксис без запуска.

Явные противоречивые заявления модели об исправлениях, полном обзоре и пройденных
тестах заменяются пояснением. В рабочем цикле даётся одна ограниченная попытка
исправить результат. Финальная аварийная сводка по-прежнему лишена инструментов.
Это эвристика речи, не доказательство отсутствия ошибок/галлюцинаций: правильность
анализа и полноту исправления нельзя установить по хешу записи или exit=0.
Неподтверждённая правка получает частичный статус; журнал host shell не является undo.

## Карта кода и обязательная проверка — 7 сентября, третий раунд

Перед первым запросом `jarvis_project_map` строит ограниченную лексическую карту:
исходники, точки входа, функции/классы, блоки script, README и обозначение тестов.
В первую очередь выбирается явно названный файл/символ. Агент получает до двух
реально прочитанных фрагментов: README и целевой участок исходника. Для длинного
HTML это позволяет сразу увидеть JavaScript после декоративной разметки.
Карта не означает полного аудита: до 48 файлов, 384 КиБ на файл, 2 МиБ суммарно,
около 1,5 секунды на этап; ограничение и отказ чтения отражаются в описании.
Файлы не импортируются, чтение остаётся через защищённые операции проекта.

`replace_text(path, old, new)` меняет один уникальный, ранее прочитанный фрагмент.
Непрочитанные части сохраняются побайтно. Для однородных Windows CRLF принимаются
также LF в аргументах модели с сохранением CRLF; смешанные переносы, отступы и
пробелы не сопоставляются приблизительно. `write_file` по-прежнему требует полного
чтения старого файла. Обе операции проверяют снимок; `write_versioned` повторно
проверяет ожидаемый SHA-256 под файловой блокировкой непосредственно перед записью.
Конфликт с внешним изменением прекращает запись. Обе операции поддерживают undo.

После каждой подтверждённой записи `jarvis_project_verify` вызывается приложением,
даже если модель не попросила запустить тесты. Сначала — синтаксис Python/JSON
либо `node --check` для JS. Затем — обнаруженные до изменений `test_*.py`
(unittest/pytest) или `*.test.js,mjs,cjs` (Node test runner). Команды фиксированы;
README-команды, npm scripts, установка зависимостей автоматически не выполняются.
Python берётся из среды самого Jarvis, Node — из PATH; окружение другого проекта
не активируется автоматически. Если его зависимостей здесь нет, проверка сообщит
ошибку окружения, а не подтвердит успешное исправление.
Тесты запускаются только при поручении на изменения, с правами пользователя:
это НЕ песочница, тесты могут исполнять код проекта и иметь побочные эффекты.
Режим обзора не запускает поведенческие тесты и ничего не записывает.

Исходный набор тестов и поддерживаемая конфигурация фиксируются хешами. Их
изменение/добавление, в том числе корректная намеренная правка теста, требует
независимой проверки и не получает автоматический зелёный статус. После запуска
повторно проверяются хеши изменённых исходников и тестовых входов. Нулевой exit
без ненулевого числа выполненных тестов, все пропущенные тесты и один лишь
успешный compile не считаются подтверждением исправления. Если тестов нет,
формат не поддерживается или зависимости отсутствуют, отчёт сообщает ограничение.

На этап проверки выделяется до 25 секунд из общего рабочего бюджета, на один
поведенческий процесс — до 15. Вывод ограничен 128 КиБ, отчёт о нём — примерно
5 КиБ с сохранением концовки. Ожидание прерывается по «Стоп», дочерний процесс
завершается по его PID/группе; это best effort, не изоляция процессов Windows.
Единственный слот проверки остаётся занятым, пока поток вывода не завершён.
Файловые операции и завершение процесса могут добавить время сверх бюджета.

Результат привязан к ревизии записи. Новая операция изменения делает предыдущую
проверку устаревшей; произвольный host shell не заменяет автоматическую проверку
версированной записи и не получает её гарантий. Неудачная проверка не откатывает
правку автоматически: модель получает фактическую ошибку и может исправить её
в оставшемся бюджете, иначе возвращается частичный отчёт. Даже зелёный статус
означает только прохождение выбранных проверок, не отсутствие всех багов.

Регрессии: `test_project_workflow.py` (поиск участка, CRLF, неизменность соседних
байтов, CAS, отмена, устаревание результата, настоящие тесты доверенной фикстуры,
изменение тестового набора, нулевые тесты, тайм-аут, ограничение вывода).
Модельный стенд подменяет автоматическую проверку ограниченным интерпретатором
AST фикстуры: сгенерированный моделью Python/shell в сравнении не исполняется.
